# AGENTS.md

Repository guidelines for AI coding agents (Codex, Claude Code, etc.) working on rui.

**rui is a fork of [qui](https://github.com/autobrr/qui).** The Go module is
`github.com/autogrr/rui`. All import paths, Docker image references, and binary
names use `rui`/`autogrr`. Do **not** revert to `qui`/`autobrr` import paths.

## Owner Collaboration Notes

- Do not implement review-suggested or extra changes outside requested scope without explicit user approval first.
- Treat other agent/Codex/CodeRabbit feedback as input to discuss, not automatic action.

## Project Structure & Module Organization

The Go backend lives in `cmd/qui` (entrypoint) and `internal/` modules for configuration,
qBittorrent, metrics, and API routing; shared helpers sit in `pkg/`.

**The primary UI is the server-rendered templ interface in `internal/ui/`** — see the
[Server-Rendered UI (templ + HTMX)](#server-rendered-ui-templ--htmx) section below.
The legacy React/Vite SPA source is archived in `web/src_legacy/` for reference; the
active `web/` tree still builds the old SPA bundle into `internal/web/dist` (used by the
REST API frontend), but new UI work goes into `internal/ui/`.

Reference docs live under `docs/`, while Docker and compose files in the repository root
support container workflows. End-user docs live in the Docusaurus project under
`documentation/docs/`. Prefer updating those for user-facing copy; `docs/` is mostly
internal/engineering notes.

Keep `README.md` concise. Feature deep-dives belong in `documentation/docs/`, not the
root README.

## Build, Test, and Development Commands

```bash
# Build
make build              # Frontend bundle + Go binary with version metadata
make backend            # Go binary only (runs templ-generate first)
make frontend           # React SPA bundle only (web/ tree)

# Server-rendered UI (templ interface)
make templ-generate     # Compile *.templ → *_templ.go (required before go build)
make templ-watch        # Watch + regenerate on file change (dev)
make tailwind-ui        # Compile Tailwind CSS → internal/ui/static/output.css
make tailwind-ui-watch  # Watch Tailwind CSS for the templ UI

# Development
make dev                # Starts air (hot-reload) + pnpm dev
make dev-backend        # Backend only with hot-reload (air)
make dev-frontend       # React SPA dev server only

# Testing
make test               # go test -race -count=3 -v ./...
make test-openapi       # Validate OpenAPI spec after touching internal/web/swagger

# Linting
make lint               # Changed files only (fast, use during iteration)
make lint-json          # JSON output to lint-report.json

# Formatting
make fmt                # gofmt + pnpm format (changed files only)
```

### templ workflow

Every `.templ` file has a corresponding `*_templ.go` generated file that must be kept in
sync. **Never edit `*_templ.go` files directly** — they are regenerated by
`make templ-generate` (or `templ generate ./internal/ui/...`). Commit both the `.templ`
source and the generated `*_templ.go` together.

### Tailwind CSS for the templ UI

The Tailwind pipeline for the server-rendered UI is separate from the React SPA. It lives
in `internal/ui/css/` and outputs to `internal/ui/static/output.css`. Run
`make tailwind-ui` after adding new Tailwind utility classes to templ files. The CSS
scanner is configured to pick up classes from all `*.templ` and `*.go` files under
`internal/ui/`.

## Server-Rendered UI (templ + HTMX)

rui replaced the React/Vite SPA with a fully server-rendered interface. The migration
plan lives in `docs/templ-migration-plan.md`.

### Technology stack

| Role | Technology |
|---|---|
| Templates | `github.com/a-h/templ` (Go templating DSL, compiles to Go) |
| Component library | templui (copy-owned, version-controlled under `internal/ui/components/`) |
| Styling | Tailwind v4 (standalone CLI, `internal/ui/css/`) |
| Interactivity | HTMX 2.x (`hx-*` attributes) + Alpine.js 3.x (`x-data`) |
| Real-time updates | HTMX SSE extension (`htmx-ext-sse.js`) |
| State/routing | SCS session manager (server-side sessions) + chi routes |
| Drag-and-drop | Sortable.js |
| Toast notifications | templui toast component |
| JS runtime | All JS is self-hosted and version-pinned in `internal/ui/static/js/` |

### Directory layout

```text
internal/ui/

  layouts/
    base.templ        # HTML shell: loads CSS, HTMX, Alpine.js, Sortable.js
    authenticated.templ # sidebar + header nav wrapper
  pages/              # Full-page templ templates (login, dashboard, torrents, …)
  partials/           # (currently empty; partial fragments live in pages/ for now)
  css/

    package.json      # standalone tailwindcss CLI dependency
  static/
    output.css        # compiled Tailwind bundle (committed; regenerate with tailwind-ui)
    js/               # self-hosted JS: htmx.min.js, htmx-ext-sse.js, alpine.min.js, …
    embed.go          # go:embed directive for static assets
  utils/
    templui.go        # templ helpers: TwMerge, random IDs, cache-busting ScriptURL
  handler.go          # Handler struct + Dependencies wiring + render() helper
  routes.go           # RegisterRoutes: all /ui/* chi routes (pages + partials + SSE)
  torrents.go         # Torrent page/partial handlers
  torrents_sse.go     # StreamTorrentsSSE — SSE endpoint for live torrent table updates
  dashboard.go        # Dashboard page/partial handlers
  dashboard_sse.go    # StreamDashboardSSE — SSE endpoint for live instance card stats
  stubs.go            # renderStub helper + placeholder handlers for not-yet-implemented pages
  …                   # one file per feature area (search, cross-seed, automations, …)
```

### HTMX patterns

- **Full page render:** handler calls `render(w, r, http.StatusOK, pages.FooPage(props))`.
- **Partial fragment (HTMX swap):** handler returns only the inner HTML snippet, not a full
  page. Routes for fragments live under `/ui/partials/…`.
- **`hx-boost`** is used on sidebar navigation links for SPA-like page transitions without
  a full reload.
- **Forms** use `hx-post`/`hx-put`/`hx-delete` + `hx-target` + `hx-swap` to update
  specific DOM regions without a page reload.
- **Alpine.js** handles micro-interactions: dropdowns, toggles, client-side form state, and
  anything that needs JS reactivity without a round-trip.

### SSE conventions

Two live-update SSE endpoints exist, both under `/ui/sse/`:

| Endpoint | Event name | Trigger |
|---|---|---|
| `GET /ui/sse/torrents?instance_id=N` | `torrent-update` | FNV fingerprint of torrent list changes (count, state, speeds) |
| `GET /ui/sse/dashboard` | `dashboard-update` | FNV fingerprint of aggregate instance stats (speeds bucketed to 50 KiB steps) |

**SSE implementation rules:**
- Always emit an initial `event: connected\ndata: {}\n\n` so the client knows the stream
  is live before the first real event.
- Set `X-Accel-Buffering: no` to disable nginx buffering.
- Emit a keepalive comment (`:\n\n`) every 15 s to prevent proxy timeouts.
- Poll the in-memory `SyncManager` cache (never hit qBittorrent directly from SSE handlers).
- Use a cheap FNV-64 fingerprint to detect changes; avoid emitting events on every tick.
- If there is no usable instance, hold the connection open (`<-ctx.Done()`) rather than
  closing it, so the client does not spin-reconnect.
- SSE handlers are triggered by the HTMX SSE extension; clients listen with
  `hx-ext="sse" sse-connect="/ui/sse/…" sse-swap="event-name"`.

### `Handler` struct

`Handler` in `internal/ui/handler.go` holds all service dependencies. All fields are
optional (nil disables the relevant page/section) except `sessionManager`, `authService`,
`instanceStore`, and `cfg`. New pages add their service pointer to both `Handler` and
`Dependencies`, then wire them in `NewHandler`.

### Component conventions

- Components live in `internal/ui/components/<name>/`. Each component directory contains
  a single `.templ` file plus the generated `*_templ.go`.
- Use `utils.TwMerge(base, extra)` (wraps tailwind-merge-go) to merge caller-supplied
  class overrides. Do not use string concatenation for class lists.
- Use `utils.RandomID()` for generating unique element IDs (e.g., for label-input pairing).
- Prefer passing a typed `Props` struct rather than individual arguments when a component
  has more than one or two parameters.

## Linting Strategy

The project uses golangci-lint v2 with strict configuration targeting AI-generated code patterns:

| Linter | Purpose | Threshold |
|--------|---------|-----------|
| dupl | Catch code duplication | 100 tokens |
| gocognit | Cognitive complexity | 15 |
| funlen | Function length | 80 lines |
| interfacebloat | Interface size | 5 methods |
| errcheck | Unchecked errors | All, including type assertions |
| gocritic | Non-idiomatic patterns | diagnostic + style + performance |

**Workflow:**
1. During implementation: `make lint` (changed files only, fast feedback)
2. To fix issues: `make lint-fix` then address remaining manually

**Guardrail (web formatting):** avoid repo-wide `pnpm format` / `eslint --fix` sweeps unless explicitly requested. Prefer fixing only the files reported by lint for the current task/PR.

## Coding Style & Naming Conventions

Keep Go code `gofmt`-clean with PascalCase exports, camelCase locals, and package-level interfaces grouped by domain inside `internal/<area>`. For the `internal/ui` package, keep handler methods in feature-named files (e.g., `torrents.go`, `dashboard.go`) and SSE handlers in matching `*_sse.go` files.

**Critical conventions:**
- Prefer explicit error handling over silent failures
- Keep interfaces small (≤5 methods)
- Avoid `map[string]interface{}` — use proper structs
- No backward compatibility shims unless explicitly requested
- **Loop variables (Go 1.22+):** Don't use `tt := tt` in parallel subtests — Go 1.22+ creates a new variable per iteration, so the old workaround is unnecessary and flagged by linters
- **templ files:** keep Go logic out of `.templ` files. Compute derived values in the handler and pass them in via a typed `Props` struct. Only presentation logic belongs in templates.
- **HTMX `hx-*` attributes:** prefer `hx-target` + `hx-swap` over `hx-select`; keep swap targets stable so HTMX does not clobber user input in adjacent fields.

**Single-user self-hosted context:** rui runs on someone's home server, not as a multi-tenant SaaS with untrusted input and complex failure modes. Skip paranoid defensive programming for impossible or purely theoretical scenarios. Code that guards against states that can't happen adds complexity without value. Prioritize readable, maintainable code over excessive robustness.

## Testing Guidelines

Place backend tests beside implementations as `*_test.go`, mirroring paths such as `internal/qbittorrent/pool_test.go`. Prefer table-driven cases and reuse the integration fixtures already in `internal/qbittorrent/`. Run `make test` before every push and add `make test-openapi` when contracts change.

When running tests, always use `-race` and `-count=3` to catch race conditions.

For changes under `internal/services/crossseed` or `internal/qbittorrent`, run targeted package tests first, then run the full `make test` suite.

There is no separate frontend test suite for the templ UI — the compiled Go tests cover handler logic. For SSE handlers, test the fingerprint logic and header assertions in unit tests; test full event streams with an `httptest.ResponseRecorder` that implements `http.Flusher`.

## Commit & Pull Request Guidelines

Follow the conventional commit style in history (`feat(scope):`, `fix(scope):`, etc.) and link issues or PR numbers in the body when relevant. Keep commits focused—split backend and UI changes when practical. Use `feat(ui):` scope for templ/HTMX work and `feat(sse):` for SSE endpoint changes.

**Never add:**
- "🤖 Generated with [Claude Code](https://claude.com/claude-code)"
- "Co-Authored-By: Claude" or any AI co-author credits
- Any advertising or attribution in commit messages

PRs need a clear summary, testing checklist, and UI screenshots for visual tweaks. Confirm `make lint`, `make test`, and a fresh `make build` succeed before requesting review.

## Pre-Commit Checklist

1. `make templ-generate` — regenerate `*_templ.go` if any `.templ` files changed
2. `make tailwind-ui` — recompile `internal/ui/static/output.css` if Tailwind classes changed
3. `make lint` passes
4. `make test` passes
5. `make build` succeeds
6. If touched `internal/web/swagger`, run `make test-openapi`

## Security & Configuration Tips

Load secrets such as `THEMES_REPO_TOKEN` via `.env` so the Makefile can fetch premium themes, and keep the file out of version control. Record configuration defaults in `config.toml` but evolve runtime schema through Go migrations rather than editing `qui.db` directly. Drop cached databases and logs (`qui.db*`, `logs/`) from commits to avoid leaking local data.

## API & Database Change Rules

- Database schema changes must ship as migrations under `internal/database/migrations` and include matching model/store updates in the same PR.
- API contract changes must update OpenAPI content under `internal/web/swagger` and pass `make test-openapi`.
- Prefer minimal, reviewable diffs in high-churn areas (`internal/services/crossseed`, `internal/qbittorrent`, `internal/models`).

## Architecture Quick Reference

```text
cmd/qui/main.go              CLI entrypoint (serve, generate-config, create-user, etc.)
internal/api/                REST API HTTP handlers + middleware (chi router)
internal/ui/                 Server-rendered UI: templ pages, HTMX partials, SSE endpoints
  ├── components/            templui component library (owned, version-controlled)
  ├── layouts/               HTML shell (base.templ) + authenticated wrapper
  ├── pages/                 Full-page templ templates
  ├── css/                   Tailwind v4 source + build config
  ├── static/                Compiled CSS + self-hosted JS (htmx, alpine, sortable, …)
  ├── handler.go             Handler struct, Dependencies, render() helper
  └── routes.go              All /ui/* chi routes
internal/qbittorrent/        Client pool, sync manager (in-memory torrent cache)
internal/services/           Domain services (crossseed, jackett, reannounce, trackerrules,
                               automations, dirscan, orphanscan, notifications, arr, …)
internal/proxy/              Reverse proxy for external apps
internal/backups/            Scheduled snapshots
internal/database/           SQLite + migrations
internal/models/             Data models + store interfaces
pkg/                         Shared utilities
web/                         Legacy React 19 + Vite SPA (src_legacy/ = archived source;
                               dist/ = built bundle embedded by internal/web)
```

**Key data flow:**
1. `SyncManager` polls qBittorrent instances via `ClientPool`
2. Torrent state cached in-memory with delta updates
3. **Server-rendered UI** (`/ui/*`): templ renders HTML; HTMX drives partial swaps;
   SSE endpoints push change notifications without polling overhead
4. **REST API** (`/api/*`): JSON endpoints for the legacy React SPA and external clients
5. Cross-seed service listens for torrent completion events
